ctfshow 命令执行web52

题目来源：ctfshow 命令执行web52
题目链接(https://b83d7aae-37e0-4319-bc65-1d82018700c8.challenge.ctf.show/)
解题思路：
启动靶机

正则过滤了分号 cat flag 空格 所有数字 $ * more less head sort tail sed cut tac awk strings od curl 反引号 % Tab键 & < >且不区分大小写
重定向被禁 换用
?c=ta\c$IFSfla\g.php||

得不到flag 原因是：shell解析过程中变量名是 $IFSfla，而不是 $IFS,Shell 会查找名为 IFSfla 的变量，但这个变量不存在 $IFSfla 被替换为空字符串
（一般情况下是$IFS$9 $9作为边界，但是这里$和9都被禁止了所以用反斜杠\)

payload:?c=ta\c$IFS\fla\g.php||
反斜杠可以做边界的原因：在Shell中，变量名由字母、数字、下划线组成 这里的反斜杠不符合该要求，所以区分开了变量名

提示flag不在该文件中 真正的flag可能在：根目录下的文件
payload:?c=ta\c$IFS\/fla\g||

得到flag

题目来源：ctfshow 命令执行web53
题目链接(https://52fb4478-1f2e-45c3-90f7-ab16360b6cef.challenge.ctf.show/)
解题思路：
启动靶机

正则过滤了分号 cat flag 空格 所有数字 * more less head sort tail sed cut tac awk strings od curl 反引号 % Tab键 & < >且不区分大小写
如果通过正则检测，执行系统命令 $c，并将命令的最后一行输出赋值给变量 $d
输出一个HTML换行标签 <br>，然后输出 $d 的值
总体实现了：命令输出直接显示在浏览器，额外显示命令的最后一行，且没有重定向，可以省去命令分割
用上一题的绕过空格的方法
payload:?c=ta\c$IFS\fla\g.php

得到flag

还有另外一种格式：
由于此题$没有被禁，所以空格可以用${IFS}代替，这个格式直接确定好了边界，无需再加反斜杠
?c=ta\c${IFS}fla?.php

得到flag

web3

题目来源：ctfshow 文件包含web79
题目链接(https://f73c96f3-2aa6-4f22-bd63-1153f9fb8e5e.challenge.ctf.show/)
解题思路：
启动靶机

GET传参赋值给参数file
$file = str_replace("php", "???", $file);
第1个参数：要查找的字符串 "php"
第2个参数：替换成的内容 "???"
第3个参数：目标字符串 $file
执行过程：查找$file中所有出现的"php"，替换为"???"
include()：PHP的文件包含函数，将指定文件的内容作为PHP代码执行
和上一题一样用data协议查看文件目录 但是为了避免php触发替换字符的命令 要对包含PHP代码的完整语句进行Base64编码
Base64编码后的字符串不包含连续的”php” str_replace无法匹配到”php”
数据在解码后才是PHP代码，str_replace发生在include之前，替换时处理的是编码后的字符串，解码在include内部进行
总结绕过原理：str_replace先执行，include后执行 并且include时才解码

payload:/?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdscycpOw==

查看flag.php文件内容

?file=data://text/plain;base64,PD9waHAgc3lzdGVtKCdjYXQgZmxhZy5waHAnKTs=

查看源码拿到flag

查看wp后发现可以直接通过大小写绕过
我根据这个思路 用了上一题的payload把php进行了大小写修改
payload:?file=Php://filter/read=convert.base64-encode/resource=flag.Php
得不到flag

原因：协议名称在流包装器注册表中是区分大小写的
所以不能用php://filter
改为使用data:// +大小写绕过
?file=data://text/plain,<?Php system('tac fla*');?>

得到flag

这里我发现了昨天那道文件包含题的问题，昨天做的时候查看源码没有响应，我今天又试了一下发现可以拿到flag
?file=data://text/plain,<?php system('cat flag.php');
查看源码同样可以得到flag

这个payload是在执行命令，而不是在读取文件内容
1.PHP接收到请求
2.PHP解析data://协议
3.PHP执行包含的代码
// 执行流程：
// 1. 解析 <?php ... ?> 标签
// 2. 执行 system('cat flag.php')
// 3. 返回命令结果
4.系统命令cat在服务器端的Shell中执行 system() 函数执行的内容cat flag.php
